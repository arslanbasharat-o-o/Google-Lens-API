# ADR-001: Managed browser adapter behind a SerpApi-compatible boundary

- **Status:** Implemented for offline/mock operation; live operation gated
- **Date:** 2026-10-17

## Context

The RMA System currently consumes a SerpApi Google Lens response and submits
multiple display images. The desired replacement must use the real Google Lens
website through a browser, but must not recreate visual search or bypass access
controls. The Hostinger VPS capacity and Google authorization are not available
to this local workspace for verification.

## Decision

Build one TypeScript/Fastify service with:

- a versioned HTTP compatibility layer (`/image`, `/search`, `/search.json`,
  `/v1/lens/search`, `/v1/lens/batch` and status aliases);
- a bounded local admission queue;
- a separate Python Scrapling worker using the documented
  `AsyncDynamicSession` API and a conservative `max_pages` setting;
- a parser that consumes a DOM snapshot, classifies challenge/loading/empty/
  parser/browser failures, and emits normalized JSON;
- SHA-256 + parameter cache keys, short image retention and Prometheus metrics;
- mock fixtures as the only default/test execution path;
- explicit live-operation gates and no anti-detection features.

Redis remains optional for offline checks. Production uses Redis persistence,
the Redis Streams Scrapling contract, and a shared file image store; the API
does not consume the same worker stream as Python. Multi-replica operation
requires those shared backends.

## Options considered

### Full Chrome process per image

Rejected. It scales the most expensive resource with input count and risks
starving the RMA application on a small VPS.

### Direct Playwright browser service

Retired. The API no longer owns a browser process or imports Playwright. Scrapling
uses Playwright internally as its documented transitive implementation detail,
while browser lifecycle and page actions remain in the Python worker.

### Scraping/stealth/CAPTCHA ecosystem

Rejected for policy and safety reasons. It would make the implementation an
access-control evasion system rather than a transparent browser integration.

### An independent visual model or vector database

Rejected because it would change the recognition backend and violate the
requested Google Lens dependency boundary.

## Consequences

The architecture is small and testable, and existing RMA clients can point at
the new service through the provider abstraction. Real-world result selectors,
latency and permission remain external risks. The release must not claim
live-operation-complete until an authorized live test and deployment check are
recorded.
